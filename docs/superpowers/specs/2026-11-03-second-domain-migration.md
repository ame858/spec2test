# 第二域迁移：把 AI × 6G 从叙事变成可演示能力

> 状态：draft
> 决策依据：ADR-0007（受众只有评委）、ADR-0008（第二域只作迁移证明）、ADR-0009（判据来源降级）
> 术语依据：`GLOSSARY.md`

## Problem Statement

作品的标题与首页主打 AI × 6G，但全部验证都发生在 NR Rel-19 的 8 个 NTN 一致性用例上。评委的第一条致命质疑是"跑题"：没有 6G 空口、没有 6G 网络、没有 AI 网元。团队既不能虚构 6G 一致性测试（6G 规范尚未冻结），也不能只靠文案解释"将来能迁移"。

结果是：技术创新度与 6G 相关性两项同时失分，而这两项占评分表的最大权重。

## Solution

在同一套六阶段流水线上新增**第二域**——AI 管理域，以 TS 28.105 的 ML 模型测试条款为输入，用 AI 生成针对 AI 网元的测试意图。产品里加一个顶部域切换器，评委可以在几十秒内亲眼看到"换一份规范，同一套机器仍然工作"。

迁移不是免费的：第二域没有官方测试用例，判据来源从**条款级**降为**过程级 + 信息模型级**。这个降级被量化成可复核的数字，并作为交付物公开，而不是被隐藏。

## User Stories

1. 作为评委，我想看到同一个产品在第二份与 AI 相关的规范上运行，这样我才会相信 AI × 6G 是能力而不是口号。
2. 作为评委，我想在界面上几秒内切换域，这样我可以自己验证这个说法，而不必听人解释。
3. 作为评委，我想被告知第二域的判据比第一域弱，这样我不会把"通过"误读成"符合规范"。
4. 作为评委，我想看到生成结果能回指到规范里的具体对象（IOC 与属性），这样我能判断它不是装饰性的演示。
5. 作为演示者，我想有一条 30 秒的切域演示路径，这样演示不会挤占主流程的时间。
6. 作为演示者，我想在一页纸上看到迁移的四个数字，这样我能回答追问。
7. 作为演示者，我想在模型不可用时仍有兜底路径，这样演示不会因为外部依赖中断。
8. 作为审阅者，我想看到第二域实际失败的例子，这样我能判断能力边界在哪里。
9. 作为审阅者，我想区分"自动判定"与"人工复核"的结论，这样我知道哪些数字是自证的。
10. 作为开发者，我想通过提供一份域配置来新增域，这样我不需要重写流水线。
11. 作为开发者，我想让校验器的跳过规则与别名从符号表读取，这样域规则不会泄漏进代码。
12. 作为开发者，我想让命令行接受域参数，这样我能在本地跑任意域。
13. 作为开发者，我想让不同域的产物写到不同目录，这样结果永远不会混在一起。
14. 作为开发者，我想有一条回归检查证明第一域行为未变，这样新增域不会静默破坏主产品。
15. 作为 API 使用者，我想让用例列表按域过滤，这样我在 ML 视图里看不到 RRC 用例。
16. 作为 API 使用者，我想让运行请求携带域，这样同一个接口服务两个域。
17. 作为评委，我想在界面上始终看到当前域，这样我不会误读结果。
18. 作为维护者，我想让收发双方与方向词汇由域配置定义，这样新域不需要改数据结构。
19. 作为维护者，我想让第二域的上下文可以从入库的基准文件重建，这样实验可以复跑。
20. 作为维护者，我想让第二域的"通过"与第一域的"通过"在文案上分开表述，这样产品不会自相矛盾。

## Implementation Decisions

- **域注册表**：一个模块拥有域的 id、显示名、基准/上下文/符号表位置、收发双方与方向词表、步骤提示词、字段提示词。域的增删只改这一处。
- **校验器**：跳过模式与消息别名改为从符号表读取；符号表未提供时回退到第一域规则。`manual_review_by_message` 存在但为空时，不得回退到第一域的额外字段表。
- **评分**：L1 的收发双方/方向词表参数化；无 gold 时 L3 记为"无"，不记为 0。
- **流水线**：六阶段骨架不变。域只决定输入位置、输出位置与提示词。
- **产物命名空间**：非默认域的通过与拒收产物都写入按域划分的子目录。
- **HTTP 接口**：用例列表与运行请求都接受域参数；缺省为第一域，保持向后兼容。
- **前端**：顶部域切换器；切换后用例库、意图、证据链整体切换；当前域始终可见。
- **域切换器形态**：采用右上**分段胶囊**（`RRC 域 | ML 域`），并入现有悬浮导航簇，常驻可见。已否决：下拉胶囊（第二个域不点开就看不见，削弱"同一套机器、两个域"的主张）与全宽作用域条（与"无顶栏、全悬浮导航"的布局冲突，需重排顶部）。
- **数据边界**：第二域的基准与符号表只存本地，不入库（遵循 ADR-0003）。
- **判据语义**：第二域无 gold，判定只由 R1/R2/R3 决定；"通过"不得表述为"符合规范"。
- **域词表**：第二域的收发双方是 `MnS consumer` / `MnS producer`，方向是 `consumer->producer` / `producer->consumer`；这是配置，不是新结构。

## Testing Decisions

- **好测试的标准**：只断言外部可观察行为——给定域与用例，得到什么判定、看到什么列表、切域后界面显示什么。不断言内部函数名、文件布局或实现细节。
- **主接缝（后端最高层）**：HTTP 接口。断言三件事：用例列表按域隔离；运行请求返回该域的判定；第一域的既有行为不变。
- **次接缝（前端）**：现有 Playwright 端到端测试。断言：切到第二域后能看到该域用例、打开后能看到步骤与证据、切回第一域后列表恢复。
- **不新增单元测试接缝**：域注册表是数据，通过主接缝间接覆盖。
- **回归基线**：第一域 gold 8 例 0 违规、缺陷集仍然全部检出；与现有确定性检查脚本同一口径。
- **先例**：现有端到端测试覆盖"运行 → 判定 → 单例页"路径；现有确定性检查脚本覆盖 gold 与缺陷集。

## Out of Scope

- 云端部署与多租户（已决定本轮不做）。
- 真实用户、客户、试点；受众只有评委（ADR-0007）。
- 超过 1–2 条 ML 条款。
- 取值级校验（枚举值、条件属性是否该出现、引用语法）——这是已知缺口，不在本轮补齐。
- 任何"已覆盖 6G"或"6G 一致性测试"的表述。
- 第三域及以后的扩展。

## Further Notes

- 首次真实运行观察到四类失败模式：枚举值非法（`requestStatus = "REQUESTED"`）、条件属性误用、引用格式畸形、`MLModel` 消息级盲区。四者都通过 R1/R2/R3，已写入迁移报告。
- 迁移报告是交付物，不是副产物；它承担 ADR-0009 要求的"降级量化"。
- 域切换器做过三方案 UI 原型（分段胶囊 / 下拉胶囊 / 全宽作用域条），选定分段胶囊。三个变体留档于 `_scratch/prototype/domain-switcher/`，不入库；主线只保留决策。
- 第二域的实验结论只支持"换域能跑通并量化降级"，不支持"能覆盖 ML 管理域"。
