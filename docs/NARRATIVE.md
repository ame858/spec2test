# 一页评委叙事（初赛）

## 作品名称
**Spec2Test：自证式测试意图编译器**

> 口径说明：本文中的“自证”指 R1–R3 三项结构不变量的确定性校验，不是独立第三方证明。校验器与缺陷注入集均由作者自建，能力边界见“诚实边界”。

## 作品简介（300–500 字，可直接粘贴）

3GPP 一致性测试用例靠人从规范里抄条款、拼步骤、填 ASN.1 字段。规范每次更新都要重核；字段漏填、消息不存在、测试目的没被覆盖，往往到联调才暴露。大模型能写，但无法被机器判错。

Spec2Test 把规范条款编译成结构化「测试意图」：测试步骤、消息序列、IE 字段，再用确定性校验器逐条判定——消息是否存在（R1）、字段是否属于该消息（R2）、每个测试目的是否被步骤覆盖（R3）。校验器只读符号表与规则，不调用模型；不合格的产物会被拒收，不写入正式结果；输入信息不足时明确弃权，不编造。

当前在 TS 38.523-1 §6.7 的 8 个 NR NTN 空闲态小区选择/重选用例上完成闭环：结构合法 8/8；注入 31 条确定性缺陷全部检出；对 8 份官方答案误报 0 条；结果可回指条款与字段，违规时给出 R1/R2/R3 路径，可导出 Markdown/JSON。

把「条款到测试意图」变成可审查、可复现的资产，先从 NTN 扩展到 AI 管理域，再扩展到更多 3GPP 系条款。6G 未标准化，在 NR Rel-19 上验证，不宣称 6G 已实现；真实性由可复现性担保。

## 一页叙事（评委视角）

### 一句话
**把 3GPP 条款编译成可执行测试意图，并用确定性校验器自证对错。**

### 为什么是现在
- NTN（卫星直连）正在从 Rel-17/18 走向商用，测试用例数量在涨，规范版本也在涨。
- 现有做法是「人读规范 + 手拼步骤 + 手填字段」，慢且不可审计；大模型能写，但写错了无法判错。
- 测试团队真正缺的不是「更多生成」，而是**生成之后谁敢签字**。

### 我们做了什么
1. **编译器**：条款 → 结构化 IR（测试目的、步骤、消息、IE 字段）。
2. **校验器**：R1 消息存在、R2 字段合法、R3 测试目的覆盖；确定性规则，不调用模型。
3. **人在环上（HITL）**：语义匹配到用例后，先展示候选消息，人工批准才调用模型。
4. **可带走**：单例页导出 Markdown/JSON，字段级证据可追溯。

### 凭什么信
| 指标 | 结果 | 口径 |
|---|---|---|
| 结构合法 L1 | 8 / 8 | 8 例均可解析为 IR；允许空 message，弃权例也计 1.0；L1_msg_cov 0.273–0.808 |
| 关键 IE 命中 L3 | 逐例给出，不报平均 | 7 例有 gold 分母（6.7.1.1 原文为 None） |
| 缺陷注入检出 | 31 / 31 | 自建 4 类模板（改名/清 TP/删 TP 步骤/塞假消息）；修正 4 条无效注入后重跑，未用真实模型错误集 |
| 真实错误集检出 | 16 / 19 | 真实模型输出人工标注；范围内 R1/R2/R3 16/16，3 条漏检为方向/顺序/完整性（校验器未声明检查）；复现 `tools/blindset.py` |
| 官方答案误报 | 0 / 8 | 校验器跑 gold IR；符号表仅 15 个消息，未覆盖消息与 LTE 的 R2 不检查 |
| 可复现 | 干净克隆自检 PASS | 本机实测 clone 1s、171ms 就绪；脚本不打印这两项。UI smoke 需本机 `app/node_modules`，否则跳过。页面/快照可复现；模型生成需同模型同温度 |

### 和「把条款贴给大模型」的区别
- 大模型输出无法被机器判错；Spec2Test 的输出先过确定性校验器。
- 不合格就**拒收**，不写入结果；信息不足就**弃权**，不生成 IE 字段内容。
- 每条结论可回指条款与字段；违规时给出 R1/R2/R3 路径。不是一段看起来合理的文字。

### 能力可迁移到哪些场景
- **规范升级回归**：规范改版后，找出受影响的用例并重新生成。
- **测试初稿与字段核对**：把条款转成可审查的意图，人工只核对字段级差异。
- **可追溯判定**：每条结论能回到条款与字段，供评审与签字。

以上是能力推演，不是已验证的用户或客户。

### 走到哪
- 现在：8 个 NTN 用例做穿，证明「条款 → 意图 → 校验 → 证据 → 导出」闭环。
- 下一步：第二域——AI 管理域（TS 28.105 §6.2c.2 + §7），用同一套六阶段骨架跑通一条 ML 测试条款，并量化判据降级。
- 更远：6G 规范冻结后，同一套「规范即 oracle」的方法可直接迁移。

### 诚实边界
- **“自证”不是独立证明**：校验器与缺陷注入集由作者自建；31/31 是自建模板上的检出。另做真实错误集盲测：真实模型输出标注 19 条，当前检出 16 条，范围内 R1/R2/R3 16/16；3 条漏检为方向/顺序/完整性。仍不是第三方盲测。
- **6G 未实现**：首个 6G 规范冻结计划 2028-12；本作品在 NR Rel-19 验证，6G 冻结后迁移同一套方法。
- **样本窄**：8 个 NTN 用例、单条款；符号表 15 个消息，LTE 条目只做 R1，R2 跳过。
- **弃权不是零模型调用**：6.7.1.4 的步骤仍含消息名，来自前序解析；阶段二未调用模型、未生成 IE 字段取值。
- **指标边界**：L1 允许空 message；L3 只衡量字段召回，不衡量取值正确；relaxed 基线在部分用例更高；L2 不计分（16 个交换）。
- **可复现边界**：页面与快照可复现；模型生成需同模型同温度，分数会波动。
- 暂无专利/软著；真实性由可复现性担保：仓库、脚本、基准、逐例结果、缺陷注入记录全部可重跑。

## 三个记忆点（评委复述用）
1. **规范就是标准答案。**
2. **校验器说不行，就不写入结果。**
3. **信息不足就弃权，不编造。**

## 评委 Q&A（预演）

**Q：为什么只有 8 个用例？**
A：8 例是「做穿」而不是「抽样」：每例都跑完生成、校验、评分、证据、导出。先用一个可审计的切片证明方法，再扩切片；不拿 100 个半成品用例充数。

**Q：有些用例 L3 不如 relaxed 基线，怎么解释？**
A：relaxed 基线去掉了路径前缀与 `-rNN` 后缀，部分用例确实更高。产品的主张不是「语义召回全面领先」，而是「ASN.1 精确 + 确定性可校验 + 允许弃权」。精确基线全 0 也说明字段命名口径差异很大，不能只看一个数。

**Q：没有专利/软著，凭什么信？**
A：用可复现性替代：干净克隆一条命令跑通；基准、脚本、结果、缺陷注入全部入库。确定性指标（校验、缺陷注入）可重跑；模型生成需同模型同温度，L3 会波动。

**Q：6G 还没标准，为什么叫 6G？**
A：不宣称 6G 标准或 6G 已实现。本作品是面向 3GPP 系测试规范的方法与工具，当前在 NR Rel-19 的 NTN 用例上验证；6G 冻结后迁移的是“规范即 oracle”的流水线，不是这 8 个用例。具体迁移对象是 NTN 测试、AI 空口测试、网络自动化测试三个方向；AI 模型性能和射频指标不归本工具判。详见 `docs/6G-RELEVANCE.md`。

**Q：6.7.1.4 有 26 步，为什么叫弃权？**
A：26 步是前序解析/步骤生成的结果，只含消息名，没有 IE 字段取值；阶段二（字段级生成）没有调用模型，因此弃权、不计分。页面和导出都按这个口径写。

**Q：这和 AI 测试生成工具有什么区别？**
A：它们优化「生成得多像」，我们优化「生成得敢不敢签字」。校验器是确定性闸门，不合格拒收、信息不足弃权，结论可追溯。
