# 第二域迁移报告（TS 28.105）

迁移实验：把第一域的六阶段流水线原样跑在 AI 管理域上，测量判据来源降级后的能力。

## 实验设置

| 项 | 内容 |
|---|---|
| 条款 | TS 28.105 §6.2c.2.1（消费者请求 ML 模型测试）+ §6.2c.3 `REQ-ML_TEST-1/2/3` + §7.3a.1b.2 信息模型 |
| 用例 | `ml.1`（`data/benchmark/ml/ml.1.json`） |
| 符号表 | 4 个 IOC、9 个属性；`MLModel` 只做存在性判定（`_partial`） |
| 流水线 | 未改动六阶段骨架；仅按域切换符号表、提示词与 `actor/direction` 词表 |
| 产物 | `data/out/ml/ml.1.json` |
| 模型调用 | 4 次（候选 4 个 IOC），生成 2 步、16 条 IE，耗时 35 秒 |

## 四个数字

| 指标 | 结果 | 口径 |
|---|---|---|
| R1 消息存在 | 2 / 2 步通过 | 步骤里出现的 IOC 名均在符号表 |
| R2 字段合法 | 9 / 9 已判字段通过 | `MLModel` 的 7 条 IE 因 `_partial` 不判 |
| R3 测试目的覆盖 | 2 / 2 个 TP 被引用 | 纯索引比对，与域无关 |
| 违规总数 | 0 | `data/out/ml/ml.1.json` 的 `violations` |
| **判定覆盖率** | **字段 0.562（9/16）· 消息 0.750（3/4）** | 被确定性规则实际判定的比例 |
| **人工复核一致率** | **0.889（8/9）** | 自审：对 9 条可判 IE 逐条核对规范 |
| **主指标（覆盖率 × 一致率）** | **字段级 0.500 · 消息级 0.667** | 有效能力，不是"通过率" |

符号表建设：4 个 IOC、9 个属性，来源 §7.3a.1b.2.1–2.3；工时为会话内完成，未单独计时。

## 判据降级的准确含义

第一域的"通过"是**条款级**：官方测试用例逐字比对，规范即答案。

第二域的"通过"是**过程级 + 信息模型级**：只判三件事——IOC 名是否存在、属性名是否属于该 IOC、每个测试目的是否被步骤引用。**不判定取值、不判定条件属性是否该出现、不判定引用格式。**

## 实测失败模式（R1/R2/R3 全部放过）

| 现象 | 生成值 | 为什么没被判 |
|---|---|---|
| 枚举值非法 | `requestStatus = "REQUESTED"` | 规范只允许 `NOT_STARTED / IN_PROGRESS / SUSPENDED / FINISHED / CANCELLED`；取值不在判定范围 |
| 条件属性误用 | 单模型请求里出现 `mLModelCoordinationGroupRef` | CM 属性的出现条件不在判定范围 |
| 引用格式畸形 | `mLModelRef = "MLModel=mlModel-001"` | 引用语法不在判定范围 |
| 消息级盲区 | `MLModel` 的 7 条 IE | 符号表只覆盖 §7.3a.1b.2，`MLModel` 未纳入 |

## 诚实边界

- **自审不是第三方复核**：9 条可判 IE 的核对由作者完成，与第一域的"自设自检"是同一类局限。
- **无 gold**：第二域没有官方测试用例，`answers` 为空，L3 记为"—"而不是 0。
- **单条款**：1 条用例不足以说明泛化；本实验只证明"换域能跑通并量化降级"，不证明"能覆盖 ML 管理域"。
- **结论**：迁移可行，但第二域的"通过"比第一域弱得多；对外材料不得把第二域的"通过"表述成"符合规范"。
